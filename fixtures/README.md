# Conformance fixtures

The executable pin on the shared contracts. Everything here is generated or
checked by [`../tools/validate-fixtures.mjs`](../tools/validate-fixtures.mjs);
run it from the repository root.

```sh
node tools/validate-fixtures.mjs   # exits 1 on any failure
```

## Layout

```
fixtures/
  wire/
    sample-blyg/     a canonical, internally consistent blyg tree (§4 surface)
    remote-blyg/     a second origin, so cross-origin constructs have a real target
  store/
    sample-store.json  the reader's private store, with deliberately secret tokens
  models/
    sample-feed.head.json    expected normalized feed window head (§7)
    sample-blogroll.json     expected normalized blogroll model (§11)
  cases/
    00-wire.json          schema validity of the wire documents
    10-vectors.json       pure-primitive vectors checked against the oracle
    20-models.json        schema validity of the normalized reader models
    30-resolution.json    §12.1–12.3, §14 discovery and fetching scenarios
    40-reconcile.json     §3, §9, §13 reconciliation scenarios
    50-composition.json   §5.4–5.9, §10, §4 composition/render/media/page scenarios
    60-webmention.json    §14–15 outbound, receive, and verify scenarios
    70-privacy.json       the fail-closed publication boundary
    80-publication.json   whole-tree publication invariants
```

`wire/**` and `store/**` are generated by
[`../tools/build-wire-fixtures.mjs`](../tools/build-wire-fixtures.mjs) and
committed. Do not edit them by hand.

## The sample blyg

A single coherent story spread across both origins, using 26-char IDs:

| Key | id | Kind | Notable |
|---|---|---|---|
| A | `1jt332depwffcsyfz9txf8c9r9` | fragment | three versions; v2 pinned; **latest content is v3** |
| B | `6y1e4khfxxckyd9dhwgrtv2dj4` | fragment | references immutable media `media/x7f2.png` |
| T | `3ev1cjtw7c6q5y8cd0r7aj3bhc` | thread | own-origin + remote + partial transclusions; a `generated` span |
| S | `7jbfafqm50v2w8xd9hkxz3yesh` | thread/stub | `stub_of` a remote item, with a frozen `cited` |
| W | `3wh683yzk9m9byd7tr17fpaxfs` | withdrawn | empty content, keeps its page and `forked_from` |
| F | `0ff73f8ranqzaf0b2n3qpxxzd7` | fragment/fork | `forked_from` a remote pinned version |
| R1 | `7gvp7ms7wq4nks6erdbbdp8cqc` | fragment | remote; pinned v1; the target of T/S/F/W |
| R2 | `5gb4pd4d8bme2zzkq7t46zkkhx` | thread | remote; the partial-quotation source |

Origins: `https://example.com/blyg/` (sample) and
`https://blyg.protocol-institute.org/` (remote).

The store holds the same secret tokens that must **never** appear in the
publication — `PRIVATE-NOTE-SECRET`, `PRIVATE-INTENT`,
`PRIVATE-INSTRUCTION-SECRET`, `DRAFT-ONLY` — plus imported rows and mention
records with reader-local fields (`watermark`, `observedAt`, `discrepancies`).

## Case format

Each file is a JSON array of cases. Every case has `id`, `description`,
`module`, `requirements` (IDs from
[`../contracts/requirements.json`](../contracts/requirements.json)), `issue`, and
`check`. The `id` is the fixture name cited by requirements. The gate fails if a
case cites an unknown requirement or if a requirement cites an undefined case.

There are five check types.

### `schema`

Validate (or fail to validate) a JSON instance against a wire schema.

```json
{
  "id": "wire.item.fragment", "check": "schema", "schema": "item",
  "input": { "$file": "fixtures/wire/sample-blyg/items/1jt332depwffcsyfz9txf8c9r9.json" },
  "expect": { "valid": true, "emitStrict": true }
}
```

`schema` names a schema (`$id` minus the `blygpress:` prefix) or use `ref` for a
`$id#/$defs/...` target. `input` is inline or `{ "$file": ... }`. `expect.valid`
defaults to `true`; `expect.emitStrict` additionally checks `x-emit-required`.

### `vector`

Check a pure primitive against the reference oracle in
[`../tools/lib/oracle.mjs`](../tools/lib/oracle.mjs).

```json
{
  "id": "vector.hash.content", "check": "vector",
  "fn": "oracle.contentHash", "args": ["…"],
  "expect": { "result": "sha256:…" }
}
```

`expect.error: true` asserts the call throws. The oracle is a **non-normative**
reference used only to keep fixtures self-consistent — it is not a product module.

### `publication`

Run named cross-file invariants against a whole publication tree.

```json
{ "id": "publication.sample-blyg", "check": "publication",
  "site": "fixtures/wire/sample-blyg",
  "assert": ["index-consistent", "pins-present", "feed-latest-content", "…"] }
```

Assertions include `manifest-surface-files-exist`, `manifest-keys-consistent`,
`index-consistent`, `index-order`, `index-includes-withdrawn`,
`updated-equals-latest-changelog`, `hashes-valid`, `pins-present`,
`no-unpinned-history-route`, `feed-guid-per-version`, `feed-link-is-page`,
`feed-entries-equal-publish-events`, `feed-latest-content`,
`feed-manifest-absolute`, `withdrawn-single-entry`, `feed-self-contained`, and
`pages-have-alternate`.

### `privacy`

Assert forbidden private tokens are absent from a publication and (optionally)
present in the store.

```json
{ "id": "privacy.sample-publication", "check": "privacy",
  "site": "fixtures/wire/sample-blyg",
  "forbidden": ["PRIVATE-NOTE-SECRET", "…"],
  "store": "fixtures/store/sample-store.json",
  "expectInStore": ["PRIVATE-NOTE-SECRET", "…"] }
```

### `spec`

A documented behavioural scenario: behaviour that cannot be exercised by data
alone is pinned as a scenario linked to real requirements. The gate checks that
the case is well-formed (`spec`, `given`, `expect.outcome`,
`expect.asserts[]`), that its `module`/`issue` match one of its referenced
requirements, and that any `artifacts` exist.

```json
{
  "id": "resolution.rel-probe", "check": "spec", "spec": "12.1",
  "module": "blyg/resolve", "issue": "SUK-139", "requirements": ["R12.1-1", "R12.1-2"],
  "given": "A subscription URL returning HTML with <link rel=\"blyg\" …>.",
  "expect": { "outcome": "The rel probe resolves to the advertised manifest.",
              "asserts": ["At most one rel hop.", "An HTTP Link header is OPTIONAL."] },
  "artifacts": ["fixtures/wire/sample-blyg/index.html"]
}
```

The implementation issues turn these scenarios into their own executable tests;
here they pin the expected behaviour and keep it traceable.

## Regenerating

```sh
node tools/build-wire-fixtures.mjs   # rewrites fixtures/wire/** and fixtures/store/sample-store.json
node tools/build-requirements.mjs    # rewrites docs/REQUIREMENTS.md
node tools/validate-fixtures.mjs     # must pass
```

`fixtures/models/*` and `fixtures/cases/*` are hand-authored and reviewed, not
generated.
